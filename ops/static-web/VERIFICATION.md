# 정적 프론트 전환 검증

실제 구현·검증일: **2026-09-26 UTC**. 커밋의 author date와 실제 수행일은 구분한다.
AWS 자원 생성·업로드·운영 도메인 변경 없이 로컬 격리 환경에서 확인한 결과다.

## 환경과 실행 범위

- Node.js 24.21.0, pnpm 11.10.0, Chromium 기반 실제 브라우저.
- Next 정적 산출물과 `serve.mjs`의 같은 출처 API 프록시 사용. Next 런타임 서버 미사용.
- 이번 확인 전용 PostgreSQL 18·Redis 7.4와 기존 Nest API 사용. 기존 마이그레이션 26개 적용 및 합성 데이터 seed 수행.
- 합성 데이터는 학생 3,382명·가족 예약 1,517건 등이며 운영 자료가 아님. SMS·Google Sheets·학생 원천 연동 비활성화, worker 미실행.
- 기존 테스트 파일과 백엔드 소스 변경 없음. 테스트 코드 작성·수정·삭제 및 테스트 스위트 실행 없음.

확인한 브라우저 흐름에서 페이지 실행 오류 수집 결과 없음. 관리자 화면 스크린샷을 통한 시각 확인 수행.
CloudFront 함수는 로컬 JavaScript 실행과 동일 함수를 사용하는 preview로 확인했으며 AWS 엣지에서 실행한 결과는 아님.

## 남은 범위와 제한

- 실제 S3/OAC/CloudFront 구성, HTTPS API 원본 연결, 최종 프록시 헤더·쿠키 설정 및 운영 전환은 미수행. [배포 계약](README.md)의 선행 조건 확인 필요.
- OTP 발송, 예약 생성·변경·취소, 실제 QR 입장, SCANNER 세션의 관리자 차단을 브라우저에서 끝까지 실행한 결과는 없음.
- BFCache 복원 시 재확인 로직은 있으나 복원 직후 이전 관리자 화면이 잠깐 보일 가능성을 코드 리뷰에서 확인. 직접 재현하거나 순간 표시까지 방지했다고 검증한 결과는 없음. 데이터 조회·변경의 최종 권한은 계속 Nest가 검사.
- 기존 서버 인증 헬퍼는 렌더 경로에서 제외했지만 파일은 보존. 업무 정책 중앙화와 계층·타입 정리는 별도 작업.
