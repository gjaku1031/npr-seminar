# iPad 스캐너 연결 디자인 핸드오프

Claude Code `fable /design` 결과를 제품 코드와 분리해 정리한 문서다. 이번 작업은 독립 앱이나 신규 관리자 모듈이 아니라 기존 `/scanner` 화면의 확장이다.

## 사용자와 핵심 작업

- 행사 당일 관리자는 입구별 iPad를 연결하고 상태를 모니터링한다.
- 게이트 스태프는 관리자에게 받은 코드만 입력하고 바로 스캔을 시작한다.
- 한 가지 핵심 작업은 “iPad 스캐너를 모호함 없이 연결하고 즉시 운영·복구한다”이다.

## 확정 흐름

1. ADMIN이 대상 슬롯과 입구 위치를 선택하고 5분짜리 1회용 연결 코드를 발급한다.
2. iPad는 6자리 코드를 입력한다. 성공하면 제한된 `SCANNER` 전용 HttpOnly 세션으로 등록된다.
3. 연결 후 관리자 화면에는 온라인 상태, 마지막 heartbeat, 배터리, 입구 위치가 표시된다.
4. 관리자는 기기 연결을 해제할 수 있다. 해제된 iPad는 즉시 코드 입력 상태로 돌아간다.
5. 네트워크가 끊긴 iPad는 재연결 중임을 명시하고 자동 복구한다. 세션이 무효하거나 해제됐으면 새 코드가 필요하다고 안내한다.

코드 상태는 발급 중, 연결 대기, 사용 완료, 만료, 발급 취소로 구분한다. iPad 입력 오류는 잘못된 코드, 이미 사용된 코드, 만료된 코드, 네트워크 오류를 서로 다른 문구로 안내한다.

## iPad 스캔 화면

`qr-poc` main의 고정 기준은 `c4194a00d3f5d87177cd131db854ae7b3ccff0f3`이다. 카메라 후면 fallback, focus, zoom, torch, 재요청과 cleanup, 동일 token 2.5초 cooldown UX를 보존한다. 서버 로직, 평문 token 저장, Server Action의 DB 접근은 이식하지 않는다.

2026-07-17 원격 브랜치를 다시 조회한 결과 위 SHA가 여전히 `main`의
최신이며 `fix/scanner-final` 병합 결과다. 구현 시 현재 NPR 이식본의 카메라
코드를 그대로 유지하지 않고 이 최종 기준으로 교체한다.

- 카메라 방향과 `1440×1080` 4:3 해상도를 스캔 시작 시 함께 요청한다.
- 시작 후 해상도를 `applyVideoConstraints`로 다시 협상하지 않는다.
- 주입된 `video`를 정사각형 `width/height/object-fit: cover`로 강제하지
  않는다. 원본 종횡비를 보존해 iOS의 ZXing 폴백 입력이 찌그러지지 않게
  한다.
- `disableFlip: true`로 반전 프레임 중복 디코드를 끈다. 전면 카메라의
  미러 표시는 CSS 표시 전용으로만 적용한다.
- iPadOS의 `Macintosh` user agent는 `navigator.maxTouchPoints > 1`로 실제
  Mac과 구분한다. iPad는 현장 거치형 전면 카메라, 휴대폰·Android 태블릿은
  후면 카메라를 우선한다.
- 현장 진단이 가능하도록 원본·표시·track 해상도와 디코더 경로를 안전한
  디버그 모드에서만 노출한다.
- QR 표시는 순수 흑백, 오류 보정 `M`, 최소 렌더 크기 224px, quiet zone
  4모듈을 유지한다. QR payload는 같은 origin의 짧은 `/q/{token}` URL이며,
  실제 제품에서는 개인별 토큰이 아니라 가족 예약 하나의 활성 credential을
  사용한다.

결과 상태는 입장 완료, 이미 입장, 다른 설명회, 취소·폐기 QR, 유효하지 않은 QR, 네트워크 실패를 색상·아이콘·문구로 함께 구분한다. same-origin `/api/v1`만 사용하며 화면에는 API나 세션 구현 용어를 노출하지 않는다.

## 기존 패턴과 새 패턴

- 재사용: 현재 TopNav, 태블릿 카드, 22px radius, 쿨그레이/화이트 표면, 네이비 잉크, 프로 블루와 스카이 강조, NanumSquareRound 제목, Pretendard 본문, 기존 Badge/Button/Dialog, 다크 전체화면 카메라.
- 신규: 5분 카운트다운을 포함한 연결 코드, iPad 6자리 코드 입력, 연결 해제 확인, 재연결 배너.

## 반응형과 접근성

- 관리자 화면은 4열 카드 또는 2패널 콘솔이 992px 이하에서 2열, 600px 이하에서 1열/하단 시트로 바뀐다.
- iPad 기준은 세로 `834×1194`다. 코드 입력 터치 영역은 최소 60px, 카메라 제어는 하단 엄지 도달 영역에 둔다.
- 코드는 단일 실제 input과 시각적 6칸 표현을 결합하고 `autocomplete="one-time-code"`를 제공한다.
- 상태는 색만으로 전달하지 않는다. 카운트다운은 초마다 낭독하지 않고 1분 단위만 `aria-live="polite"`로 알린다.
- 연결 해제 확인은 `alertdialog`, 포커스 트랩, 취소 버튼 기본 포커스를 사용한다.

## 시각안 세 방향

- 1: 빈 장치 슬롯이 코드 발급과 연결 대기 상태로 자연스럽게 바뀌는 카드 중심 구조.
- 2: 큰 코드와 카운트다운에만 집중하는 기존 Dialog 중심 구조.
- 3: 장치 목록과 선택 장치 상세를 분리한 운영 콘솔 구조.

사용자가 1, 2, 3 중 하나를 명시적으로 선택하기 전에는 `apps/web`을 구현하지 않는다.
