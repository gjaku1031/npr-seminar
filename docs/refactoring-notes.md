# 코드 정리 기록

기존 기능을 유지하면서 정책의 기준과 HTTP·업무 처리·데이터 조회의 책임을 읽기 쉽게 정리한 기록. 실제 구현·검증 시점은 2026-09-26 이후이며 커밋의 author date 배치와 구분. 운영 배포·성능 개선 실적으로 해석하지 않음.

## 문자 편집 정책

### 문제

문자 화면의 용도별 변수 버튼과 서버의 허용 변수 검증이 각각 고정 목록을 관리하는 구조. 한쪽만 수정하면 화면에서 넣을 수 있는 변수를 저장 시 서버가 거절할 수 있음.

### 변경

`apps/api/src/modules/sms/sms-template-policy.ts`가 기존 6개 서버 용도의 변수 집합과 편집 화면에 필요한 정보를 정의. 렌더러·DTO와 관리자 정책 조회가 같은 선언을 사용. 기존 허용 변수와 FIRST_CHECK_IN의 서버 처리 범위 유지.

`GET /api/v1/admin/sms/template-policy`는 ADMIN에게 기본 용도와 편집 가능한 5개 용도의 `purpose`, `label`, `variables`, `keyPrefix`를 반환. DB 조회와 문자 발송 없음. Controller는 인증된 HTTP 진입점, Service는 정책 조회, 렌더러는 저장·발송 시 변수 검증 책임.

브라우저는 응답으로 용도 선택지·라벨·변수 버튼·신규 템플릿 키 접두어 구성. 응답을 읽지 못하면 고정 목록으로 대신 진행하지 않고 해당 편집 동작을 잠근 뒤 재시도 안내. 입력·커서·로컬 예시 문구 등 화면 표현은 브라우저에서 유지.

기존 테스트가 직접 import하는 `entities/sms/model/template-purpose.ts`는 호환 목적으로 보존하며 제품 런타임 참조는 제거. 저장소 전체의 고정 목록을 모두 삭제한 변경은 아님. HTTP 계약의 용도 타입과 응답 구조 검사는 프론트에도 존재하며 실제 용도별 허용 변수는 서버 응답 사용.

### 검증

API 타입검사·빌드, Web 타입검사·린트·정적 빌드, OpenAPI 검증 통과. Web의 기존 생성 타입이 삭제된 동적 예약 경로를 참조했던 최초 검사는 실패했으나 정적 빌드로 생성물을 갱신한 뒤 통과. 새 조회 훅의 린트 지적은 수정 후 재확인.

격리 PostgreSQL 18·Redis 7.4·Nest와 합성 데이터에서 다음을 확인. 외부 SMS·학생 원천·Google Sheets와 worker 비활성화.

| 항목 | 결과 |
| --- | --- |
| 기존 `10cd5b7` 변수 정의 비교 | 6용도의 허용 변수와 순서 동일 |
| 직접 렌더러 확인 | 허용 변수 34개 성공, 용도 외 변수 14개 거절 |
| 정책 조회 권한 | ADMIN 200, 익명 401, 실제 페어링한 SCANNER 403 |
| 템플릿 API | 잘못된 변수 400, 생성 201·수정 200·재조회 저장값 일치 |

실제 정적 프론트에서 예약 취소의 변수 칩 6개(인증번호·QR 제외), 변수 삽입 후 입력 초점 유지, 저장 후 재진입 시 본문 반영 확인. 브라우저 요청 차단으로 첫 정책 조회 실패를 모의 주입하여 편집 잠금·오류 안내·재시도 버튼을 확인하고, 차단 해제 후 편집 복구 확인. 이 장애는 실제 운영 장애가 아닌 검증 조건.

테스트 코드·테스트 스위트는 변경하거나 실행하지 않음. 운영 배포·실제 문자 발송 결과 아님. 리뷰에서 발견한 기존 템플릿 생성 재시도 문제는 후속 수정으로 분리.
