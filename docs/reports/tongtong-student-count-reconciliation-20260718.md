## 캠퍼스별 단계 집계

적용 순서는 사용자가 지정한 규칙과 같다.

1. 통통통에서 재원생 조건 조회
2. 원천 상태가 정확히 `재원생`인지 확인
3. 반명에 `[` 또는 `]`가 들어간 배정 제외
4. 남은 배정을 학번으로 중복 제거
5. 결과 학번 집합과 PostgreSQL의 활성 학생 집합 비교

`원천 배정 행`은 학생 수가 아니라 반 배정 행 수다. 한 학생이 여러 반에 속할 수 있으므로, 학생 수는 반드시 제외 규칙 적용 후 학번을 중복 제거해서 계산한다.

`상태 재검증 제외`가 0인 것은 원천 요청 자체에 이미 `재원생(NN)` 조건을 적용했고, 수신한 각 행의 상태도 다시 `재원생`인지 확인했기 때문이다.

## 교차 검증

한 숫자만 믿지 않고 다음 세 계층을 각각 비교했다.

1. 성공 실행에 기록된 캠퍼스별 `branchCounts`
2. 같은 실행의 staging 행을 규칙대로 다시 집계한 값
3. 현재 PostgreSQL `students.source_active = true` 집합

`branchCounts`와 staging 재집계는 모든 단계에서 같았다. staging에서 선택·게시된 `(캠퍼스, 학번)` 집합과 현재 활성 학생 집합의 차집합도 각 캠퍼스 모두 `0 / 0`이었다.

기존 요구사항인 “학번은 전 캠퍼스에서 유일”도 별도로 검사했다. 최신 성공 실행의 `included AND primary_selected` staging과 현재 `students.source_active = true` 양쪽 모두에서, 같은 학번이 둘 이상의 캠퍼스에 존재하는 경우는 **0그룹 / 0행**이었다.
